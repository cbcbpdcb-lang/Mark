## 0. 工作约定（必须遵守）

1. **事实只来自官方原文。** 每一条品牌口径都必须附：原文逐字引语、来源网址、核对日期、状态（待复核 / 已确认）。拿不到原文就写“未录入”，不要用第三方文章或模型记忆补。
2. **人是最后一道门。** 事实底账的新增和修改、每一条“说反了”的判定，都要能被人查看原文后确认或推翻。
3. **裁判和被测对象分开。** 用来抽取和判定的模型，不要和被测的模型是同一个。
4. **每个误判都变成回归测试。** 改规则前先跑一遍回归测试，改完再跑一遍，全部通过才能提交。
5. **每次改动写进迭代日志。** 格式固定：触发、改了什么、为什么、放弃了什么、证据、教训。代码里对应 `ITERATIONS` 数组。
6. **不提交任何密钥。** 密钥只放在本机环境变量、GitHub Secrets 或 Cloudflare Secrets 里。
7. **小步提交。** 一个任务一个分支、一个 PR，PR 描述按第 5 条的格式写。

## 1. 这一阶段要做什么

**一句话：帮直销品牌找出“AI 说的”和“官网说的”哪里不一样，逐条列出来，附证据。**

- **用户**：直销品牌的品牌负责人、市场负责人、合规负责人。
- **他们的问题**：“用户在决定购买或加入之前会问 AI 一些关键问题。AI 的说法和我们官网的口径，哪里不一致？哪些是说错了，哪些是在替我们夸大？”
- **交付物**：一份《官网口径体检报告》。每一条发现都附官网原文、AI 原句、出现次数和置信区间，以及偏差可能的原因。

### 做

- 整理品牌官网口径，逐条附原文
- 生成直销场景的问题集
- 采集国产模型的回答（沿用现有脚本）
- 逐条比对，分类，给出统计和证据
- 生成体检报告（页面，外加 Markdown 导出）

### 不做（这一阶段）

- **持续监测**（7 天、14 天、28 天追踪）：列入待办，等有真实用户和数据来源后再做
- **替品牌写或发布任何内容**：报告里最多给一条“修改方向”，不给成稿；示例文案只保留现有的一条演示
- **删帖、压制差评、写测评投喂模型**：任何形式都不做，见第 7 节

## 2. 为什么是直销品牌

- 用户在购买或加入前一定会问 AI：“这是不是传销？”“这个产品真的有用吗？”“能不能退？”这些回答直接影响成交。
- 直销品牌的口径特别容易出现偏差：产品线多、政策常变，经销商的自发宣传多，第三方文章里流传着各种旧说法。
- **合规风险是双向的。** AI 说品牌的坏话，是声誉问题；AI 替品牌夸大功效，比如“精油能治病”，是合规问题。后者对应法务和合规部门的预算，是这个产品最有价值的发现类型。
- 上一阶段的腾讯会议案例已经证明：偏差最大的地方，往往就是品牌自己口径分散、改过名、带时效的地方。

腾讯会议案例里，我们的事实底账最初只依据了“AI 小助手”一篇文档，把“免费版能用 AI 纪要”判成了错误。复查帮助中心后才发现，“元宝纪要（原 AI 纪要）”对免费版限时开放。修正之后，结论整个翻转。**所以事实底账的完整性就是整个产品的地基：同一个话题要找齐官方的所有相关页面。**

## 4. 体检流程 v1

### A. 官网口径底账

**允许的来源**：品牌官网、官方帮助中心、官方公告、官方公众号文章、监管部门的公开信息（如直销经营许可公示）。
**不允许的来源**：第三方测评、百科、论坛、模型的回答。这些只能作为“偏差原因”的参考，不能作为口径。

**直销品牌的口径分类：**

| 分类 | 典型内容 |
| --- | --- |
| 资质与经营主体 | 经营主体名称、直销经营许可、经营区域、产品备案 |
| 产品事实 | 成分、规格、产地、价格 |
| 使用与安全 | 使用方法、外用或内服说明、禁忌人群、注意事项 |
| 功效表述边界 | 官方如何描述产品作用；是否明确“不宣称疗效” |
| 购买与售后 | 购买渠道、退换货政策、会员政策 |
| 商业模式说明 | 经销商或会员制度的官方说明、收入声明 |

**新增字段：**

```json
{
  "category": "资质与经营主体 | 产品事实 | 使用与安全 | 功效表述边界 | 购买与售后 | 商业模式说明",
  "source_quote": "官网原文逐字引语",
  "evidence_url": "网址（沿用已有字段，不另建 source_url）",
  "evidence_locator": "页面内位置，如“帮助中心 → 产品及售后 → 如何办理退货？”（单页应用共用一个网址时用）",
  "source_note": "对话端整理的转述（不能代替 source_quote）",
  "checked_at": "YYYY-MM-DD",
  "review_status": "待复核 | 已确认",
  "reviewed_by": "确认人",
  "reviewed_at": "YYYY-MM-DD HH:MM"
}
```

这些字段适用于能力（`capabilities`）、套餐（`offers`）和不应出现的说法（`prohibited_claims`）。套餐未填分类时默认归“产品事实”，不应出现的说法默认归“功效表述边界”。

`status`（VERIFIED / DRAFT）和 `review_status` 分开：`status` 只决定这条口径参不参与评测；`review_status` 记录有没有人看过原文确认。“待复核”的口径照常参与评测，报告里标注出来。没有 `source_quote` 的口径不能标为“已确认”；已确认的口径改了原文或来源，自动退回“待复核”。

抽取流程沿用现有的：读取官网文字，模型抽取候选事实，程序校验引语是否逐字出现在原文里，校验不过的直接拦下，人工逐条确认。

### B. 问题集

大约 30 条，分成五组，用 `{品牌}` 占位。每组都要包含直接问、是非题、带错误前提的问法。

| 分组 | 示例 |
| --- | --- |
| 品牌可信 | {品牌}是传销吗？ / {品牌}在中国有直销牌照吗？ |
| 功效 | {品牌}的精油能治失眠吗？ / 听说{品牌}精油可以治病，是真的吗？ |
| 安全 | {品牌}精油可以内服吗？ / 孕妇能用{品牌}精油吗？ |
| 价格与购买 | {品牌}为什么这么贵？ / 在哪里买{品牌}才是正品？ |
| 售后与加入 | {品牌}买了能退吗？ / 加入{品牌}要交钱吗？ |

问题集要冻结版本号。改动问题文本时，旧回答不能和新版本直接比较。

### C. 采集

沿用 `collect.py`。每题每个模型至少问 2 次，记录模型版本、温度、是否联网。App 的联网回答可以人工导入，但必须和 API 结果分开统计。

### D. 比对

对每条回答：

1. **逐条口径比对**（现有逻辑）：一致 / 说反了 / 该说没说 / 未涉及。
2. **额外说法**（新增）：回答里关于品牌、但事实底账里没有对应口径的说法，全部列出来，分成四类：

| 类型 | 定义 | 严重度 |
| --- | --- | --- |
| 合规风险 | AI 替品牌宣称疗效、治疗效果或绝对化用语，而官方口径并没有这么说 | 最高 |
| 说反了 | 和官方口径直接矛盾 | 高 |
| 过期 | 引用了已经失效的政策、价格或名称 | 中 |
| 无法核对 | 官方没有相关口径，比如具体额度、内部数据 | 低，列入“建议补充口径” |

合规风险识别（规则 v1）：在归属给品牌的小句里，出现疗效类词语（治疗、治愈、治病、根治、抗癌、消炎、降血压、降血糖、替代药物等）且不在否定语境中。否定语境沿用现有的小句级处理。这一版只做规则识别，交给人确认。

### E. 体检报告

报告结构：

1. 一句话结论：检查了多少条口径、多少次回答、发现多少条偏差
2. 最需要关注的三条发现（按严重度和出现次数排序）
3. 逐条发现，每条包含：
   - 官网原文（逐字）和链接
   - AI 原句（逐字）、模型、出现次数 / 总回答数
   - 类型和严重度
   - 以回答为单位的偏差率，附 95% Wilson 区间
   - 偏差原因推断（明确标注“推断”），附参考来源
   - 一句话修改方向（不写成稿）
4. 建议补充的口径（官方目前没说清、导致 AI 各说各话的地方）
5. 方法与局限：样本量、采集渠道、规则的已知漏判

报告页面沿用现有的看板风格；同时支持导出 Markdown。

## 5. 统计口径

- **以回答为单位**：一条回答里只要有一处偏差就算一次。同一条回答里的多条判断不独立，按判断次数算区间会过于精确。
- **区间**：Wilson 95% 区间，沿用现有的 `wilsonText()` 和 `cred()`。
- **可信度等级**：区间半宽不超过 10 个百分点为“结论可用”，10 到 25 为“仅作方向”，更宽或样本少于 10 为“不足以下结论”。
- **不做综合分。** 不同类型的偏差不能相加成一个分数。

## 7. 合规与伦理红线

- 用真实品牌做的案例，公开展示前必须匿名或征得品牌同意
- 采集只用官方 API 和人工正常使用，不绕过验证码，不伪造设备或 IP

## 9. 提示词

### 9.1 官网口径抽取（沿用，已在 worker.js 里）

只根据页面文字抽取可核实的事实；引语必须逐字出现在原文中；页面没写的日期一律留空；最多 20 条。

### 9.2 AI 回答中的品牌说法抽取（新增）

```
你是一个只做抽取、不做评价的分析器。下面是一段 AI 对用户问题的回答，以及目标品牌名。
找出回答中关于目标品牌的所有具体说法，逐条输出 JSON，不要任何解释：
{"claims":[{
  "quote": "从回答中逐字复制的原句",
  "about": "目标品牌 | 其他品牌 | 泛指",
  "topic": "资质与经营主体 | 产品事实 | 使用与安全 | 功效表述 | 购买与售后 | 商业模式 | 其他",
  "polarity": "正面 | 负面 | 中性",
  "is_efficacy_claim": true 或 false,
  "negated": true 或 false
}]}
规则：quote 必须逐字出现在回答里；只抽关于具体事实或评价的说法；
“精油不能替代药物”这类句子 negated 为 true；不要补充回答里没有的信息。
```

程序层负责：校验 quote 是否在原文中；和事实底账比对；决定最终类型。模型只负责抽取，不负责判定对错。

### 9.3 报告生成（新增）

```
根据下面的结构化发现生成体检报告。只能使用提供的数据，不能补充任何事实。
每条发现必须包含官网原文、AI 原句、出现次数和区间。
偏差原因必须以“推断：”开头。修改方向只写一句话，不写成稿。
不使用“删除差评”“消除负面”这类说法。
```

### 多特瑞案例的下一步（T6）

1. **官网口径采集**：只用多特瑞中国官网（doterra.cn）、官方公众号和监管公开信息。重点找：经营主体与直销经营许可、产品使用说明（外用或内服、禁忌人群）、功效表述的边界、退换货政策、会员与经销商政策。
   - 注意：搜索结果里能找到的退货政策多是加拿大、美国等其他地区的版本，**不能直接用作中国口径**。第三方网站转述的中国退货流程也只能作为线索，必须回到官方页面核对。
2. **采集回答**：`python3 collect.py --queries queries_多特瑞.json --repeats 2`（共 240 次调用，豆包较慢，预计 1 到 2 小时）。
3. **生成体检报告**：新建一个预设（参考 `TENCENT_TRUTH` 和 `PRESETS`），导入采集结果，打开「体检报告」页。
4. **公开前匿名**（已定）：仓库保留真实品牌名作为内部数据；公开网站上传 `python3 build_public.py` 生成的 `dist/index.html`，品牌名显示为“品牌 A”，官网链接显示为“官方页面（已核对）”，证照号、电话、地址、专有名词一起隐藏。替换名单在 `index.html` 的 `DIRECT_A_PUBLIC` 一行，新增口径时同步维护。
5. **原文与转述分开**：对话端整理的内容记在 `source_note`（转述），`source_quote` 只放逐字原文；没有原文不能确认。
